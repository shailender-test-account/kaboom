Smoke-test checklist
  • ☐ scenario_selected fires when a scenario card is clicked
  • ☐ registration_completed fires with contact email attached
  • ☐ entry_submitted returns tracked:true
  • ☐ pf:identify sent → buffered events replayed with identity
  • ☐ pf:resize received and iframe height applied

ℹ page_view fires before the spy is injected and will not appear in this log. Verify it in the server logs or a network proxy (e.g. browser DevTools → Network).

Cookie-partitioning limitation: when embedded cross-domain, the browser may block the pf_vt cookie (Chromium, Safari ITP). Pre-registration events will land on an anonymous shadow contact and be merged once the registration form is submitted with a known email.

postMessage workaround: if the embedding page knows the visitor's identity (e.g. from a CRM widget or SSO session), it can post { type: 'pf:identify', email, cid } to the iframe at any time. The contest page will update its identity state and replay any buffered pre-identification events with identity attached so the server can retroactively link them to the correct contact.

Trust gates: the listener only accepts messages from window.parent (direct embedding page only) whose origin matches this page's own origin or an explicit <meta name="pf:embed-trusted-origin" content="https://partner.example.com"> declared inside the contest page. Messages from any other window or origin are silently dropped. Raw cid values are additionally restricted to same-origin parents only — cross-origin partners should send email and use a server-signed embed token for strong contact-ID binding.

Do not pass a raw contact ID in the embed URL — sequential IDs are guessable and would let any third party poison another contact's activity log.
